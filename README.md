# GoMeet

Google Meet-style video call app (Angular + Capacitor + LiveKit + Firebase) with one extra
feature: any participant can swap their real camera for a pre-recorded looping video (with audio),
published in place of their own camera, without leaving the call.

## Structure

```
fakevideo/            Angular app (web + Capacitor). All the front-end lives here.
  src/app/pages/         join-room (start screen) and call-room (call screen)
  src/app/components/    video-tile, controls-bar, participants-panel, chat-panel, media-switch-modal
  src/app/services/      livekit.service, media-source.service (the core of the media switch),
                         clip-library.service, room.service, firebase-app, current-user
  android/, ios/         native projects generated by Capacitor
netlify/functions/     Netlify Functions: generateLiveKitToken, createRoom (replace the old Firebase Functions)
firestore.rules        Firestore rules (rooms + clip library)
firebase.json          Firebase config (Functions + emulators)
```

## How it all connects

- The front-end never talks directly to the LiveKit API using the secret key. It calls the Cloud
  Function `generateLiveKitToken`, which generates a server-signed JWT and returns it along with
  the LiveKit URL.
- Authentication is anonymous (Firebase Auth `signInAnonymously`) just to give each device a
  stable `uid` — used to know which personal clips belong to whom, without requiring signup/login.
- The camera ↔ clip switch (`media-source.service.ts`) works like this: the clip plays on loop in
  a hidden `<video>`, `video.captureStream(30)` generates a `MediaStream` with video+audio, and
  those tracks replace the published tracks via LiveKit's `LocalTrack.replaceTrack()` — no
  unpublish/publish, no renegotiation, no flicker in the call for the other side.

## Running locally (no cloud accounts needed, 100% free)

Everything works locally: a development LiveKit server + the Firebase Emulator Suite (just
Firestore/Auth) + `netlify dev` (running the Angular app, the functions, and local Netlify Blobs
together).

### 1. Local LiveKit

```bash
brew install livekit
livekit-server --dev
```

Brings up LiveKit at `ws://localhost:7880` with the default development credentials
(`devkey` / `secret`) — already configured in the `.env` file at the project root.

### 2. Firebase Emulator Suite (Firestore + Auth — no Functions or Storage)

Requires **Java 21+**.

```bash
firebase emulators:start --only firestore,auth
```

Emulator UI is at http://127.0.0.1:4000.

### 3. Angular app + Netlify Functions together

```bash
npm install -g netlify-cli   # only the first time
cd fakevideo && npm install && cd ..
netlify dev
```

Opens `http://localhost:8888` (not `4200` — that's the `netlify dev` port, which already bundles
the Angular app and both functions in one place) in two different tabs/browsers to simulate two
people in the same room.

The `.env` file at the root already comes filled in with everything needed for this to work
without signing up anywhere: local LiveKit + Firestore emulator.

### Testing clip upload

Each person uploads their own pre-recorded clip directly through the app ("Switch media" modal →
"Upload clip"). The file goes to Netlify Blobs (locally: an isolated store from `netlify dev`; in
production: the site's real Blobs) and only the metadata (name, owner) goes to Firestore. There's
no curated "shared" library in this first version — each participant uses the clips they
themselves uploaded, which is already enough for the gag (the clip is published as the person's
own camera during the call; other participants never need to access it directly).

## Going to production — also 100% free, no credit card

Firebase Cloud Functions requires the paid Blaze plan even for free-tier usage, so this project no
longer uses Firebase Functions: the three functions that need a server (generating a LiveKit
token, creating a room, and uploading/serving a clip) became **Netlify Functions**, which run for
free without asking for a card. For the same reason, clip video files go to **Netlify Blobs**
(also free, included in Netlify's free plan) instead of Firebase Storage — since Sept/2024 Google
requires the Blaze plan just to create a new Storage bucket, even if usage stays free. Firebase,
here, only handles Firestore + anonymous Auth, which remain free on the **Spark** plan (no card
required).

1. **LiveKit Cloud** (*Build* plan, free, no card — 5,000 participant-minutes/month included):
   create a project at https://cloud.livekit.io and copy, under *Settings > Keys*, the WebSocket
   URL, the API Key, and the API Secret.
2. **Firebase** (*Spark* plan, free, no card — **do not upgrade to Blaze**): create a project at
   https://console.firebase.google.com, enable Firestore (production mode) and Authentication
   (Anonymous method). **Do not enable Storage** — it requires upgrading to Blaze. Under *Project
   settings > Service accounts*, click "Generate new private key" — this downloads a JSON file
   with `project_id`, `client_email`, and `private_key`, which is what the Netlify Functions use to
   write to Firestore without needing an authenticated client SDK.
3. Update `fakevideo/src/environments/environment.ts` with the real Firebase web config
   (*Project settings > General > Your apps > `</>` Web*).
4. **Netlify** (free, no card): create an account at https://app.netlify.com, "Add new site >
   Import an existing project" (connects to GitHub) or run `netlify deploy` via the CLI directly
   from this folder. Configure the site's environment variables (*Site configuration >
   Environment variables*) with the contents of `.env.example`: `LIVEKIT_URL`, `LIVEKIT_API_KEY`,
   `LIVEKIT_API_SECRET`, `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`
   (the private key from the JSON, with the `\n` line breaks kept as they appear in the file).
5. Deploy the Firestore rules (no Blaze needed for this):
   ```bash
   firebase deploy --only firestore:rules
   ```
6. `netlify deploy --prod` (or let Netlify build automatically on every push, if connected via
   GitHub) — the build command already compiles Angular in production mode.

At the end of these steps you'll have a public URL (something like `fakevideo-xxx.netlify.app`)
that anyone can open in a browser, from any network, at no cost as long as usage stays within each
service's free quotas (well above what a fun test with your team consumes).

## Responsible use

Swapping a camera for a recorded clip only shows as marked (clapperboard icon) on the screen of
whoever is controlling that participant — for everyone else, the video appears normally, as if it
were the real camera. Use only in contexts where all participants know about and consent to the
gag or test; avoid scenarios that rely on verified real presence (exams, interviews, etc.).
